# Origin Protocol v0 — Interoperability Fixtures

This directory is the byte-equality reference for an Origin-Protocol-v0-conformant implementation. Every artefact here was generated by `gen.go` and is re-verified by `fixtures_test.go` on every `go test ./...` run.

## How to use these fixtures

If you are implementing Origin v0 in another language or codebase, your implementation is conformant when:

1. Reading `identity/<name>.json` as JSON, applying RFC 8785 canonicalisation, and producing bytes byte-equal to `identity/<name>.canonical-bytes`.
2. Hashing those bytes with SHA-256 and producing the hex string in `identity/<name>.expected-id` (and matching the `id` field inside the JSON).
3. Producing the same canonical bytes / IDs for the occurrence and claim fixtures, per the protocol §3-§5.
4. Signing the occurrence canonical bytes with the published test signing key and producing the signature in `occurrence/<name>.expected-signature`.

## Test signing key

`keys/test-signer.pub` and `keys/test-signer.ed25519` contain a deterministic Ed25519 key pair derived from the SHA-256 of the string:

```
origin-protocol-v0-fixture-signing-key
```

The fingerprint (first 16 hex chars of `SHA-256(public_key_bytes)`) is whatever you compute from the key.

**This key is for fixture reproducibility ONLY. It MUST NOT be used to sign production assertions.** A conformant production implementation MAY refuse to load this fingerprint as a trusted signer. The `gen.go` documents the seed string so anyone can regenerate the same key from scratch.

## Regenerating fixtures

```
cd protocol/v0-fixtures
go run gen.go
```

The generator overwrites every file in this directory except `README.md` and the test files. After regenerating, run `go test ./protocol/v0-fixtures/` from the repo root to confirm the new fixtures still round-trip correctly.
